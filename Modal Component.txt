ინტერაქციული აპლიკაციის შექმნისას ხშირად გვჭირდება მომხმარებლის ყურადღების მიპყრობა კონკრეტულ დავალებაზე ან მოქმედებაზე (მაგალითად, ინფორმაციის დადასტურებაზე ან ფორმის შევსებაზე) ისე, რომ ის სხვა ეკრანზე არ გადავიყვანოთ.

ასეთი შემთხვევებისთვის შეგვიძლია გამოვიყენოთ <Modal> კომპონენტი:

const [isEditorVisible, setIsEditorVisible] = useState(false)
const [name, setName] = useState(user.name)

<Modal
  visible={isEditorVisible}
  animationType="fade"
  onRequestClose={() => setIsEditorVisible(false)}
>
  <View>
    <Text>User: John123</Text>
    <TextInput value={name} onChangeText={setName}/>
    <Button title="Cancel" onPress={() => setIsEditorVisible(false)}/>
    <Button title="Save" onPress={() => {
      { /* მომხმარებლის შენახვის ლოგიკა */ }
      setIsEditorVisible(false)
    }}/>
  </View>
</Modal>


მოცემულ მაგალითში ჩვენ:

    -ვარენდერებთ პატარა ფორმას <Modal>-ის შიგნით.

    -visible თვისებას (prop) ვუტოლებთ isEditorVisible-ს, რომელიც აკონტროლებს, თუ როდის გამოუჩნდება მოდალური ფანჯარა მომხმარებელს.

    -onRequestClose თვისება (prop) იყენებს იმავე ლოგიკას, რასაც <Button>-ის onPress, რათა დახუროს მოდალი, თუ მომხმარებელი მასზე დააჭერს. ეს აუცილებელია იმისთვის, რომ მომხმარებელმა შეძლოს მოდალის დახურვა მაშინაც კი, თუ ის არ დააჭერს ღილაკს.

    -animationType თვისება (prop) განსაზღვრავს, თუ როგორ გამოჩნდება მოდალი (მაგალითად, fade, slide, none).

    -მოდალის შიგნით ვარენდერებთ <Text>, <TextInput> და <Button> კომპონენტებს, რომლებიც გამოიყენება მომხმარებლის მონაცემების ჩვენებისა და რედაქტირებისთვის.


    მარტივად რომ ვთქვათ, <Modal> არის „ზემოდან გადაფარებული“ ფანჯარა.

    ის „ფარავს“ ეკრანის ნაწილს ან მთელ ეკრანს და აიძულებს მომხმარებელს, რომ დაასრულოს კონკრეტული მოქმედება, სანამ ის გააგრძელებს აპლიკაციის გამოყენებას.


    წარმოიდგინე, რომ აპლიკაციაში რაღაცას აკეთებ (მაგალითად, სიას ათვალიერებ) და უცებ ეკრანზე ამოხტება პატარა ჩარჩო, რომელიც გთხოვს: „დაადასტურეთ წაშლა“ ან „შეიყვანეთ პაროლი“. ამ დროს ძირითადი ეკრანი არსად გამქრალა, ის უბრალოდ ამ ახალი ფანჯრის უკანაა მოქცეული.

აი, მთავარი პრინციპები, რაც უნდა დაიმახსოვრო:


1. რატომ ვიყენებთ?

    -ყურადღების მისაპყრობად: მომხმარებელი ვერ გააგრძელებს სხვა რამეს, სანამ მოდალს არ დახურავს ან მასში მოქმედებას არ შეასრულებს.


    -კონტექსტის შესანარჩუნებლად: არ გიწევს ახალ ეკრანზე გადასვლა (Navigation). რჩები იქ, სადაც ხარ, უბრალოდ დამატებით ინფორმაციას იღებ ან აწვდი.


2. მთავარი პარამეტრები (Props).

    -visible: ეს არის ლოგიკური მნიშვნელობა (true/false). თუ true — მოდალი ჩანს, თუ false — იმალება.

    -animationType: განსაზღვრავს, როგორ გამოჩნდება მოდალი. ყველაზე ხშირად იყენებენ: "slide" (გვერდიდან ამოდის), "fade" (ნელ-ნელა ჩნდება), "none" (მყისიერად ჩნდება).

    -onRequestClose: ეს არის ფუნქცია, რომელიც სრულდება მაშინ, როცა მომხმარებელი ცდილობს მოდალის დახურვას (მაგალითად, უკანა ღილაკით ან ეკრანის გარე ნაწილზე დაჭერით, თუ ეს დაშვებულია).

    -transparent: თუ true, მოდალის ფონი გამჭვირვალე იქნება და გამოჩნდება ძირითადი ეკრანის შიგთავსი. თუ false, ფონი იქნება შავი და დაფარავს ყველაფერს.


    3. როგორ მუშაობს? (ლოგიკა)

    -თავიდან მოდალი ყოველთვის დახურულია (visible = false).

    -როცა გინდა, რომ გამოჩნდეს, ცვლი ლოგიკურ მნიშვნელობას true-ზე.

    -როცა მომხმარებელი ასრულებს მოქმედებას (მაგალითად, აჭერს „შენახვას“ ან „გაუქმებას“), შენ ისევ ცვლი მნიშვნელობას false-ზე და მოდალი იხურება.


    4. როდის გამოვიყენოთ?

    -როცა გჭირდება მომხმარებლისგან სწრაფი დადასტურება (დიახ/არა).

    -როცა უნდა აჩვენო შეტყობინება, რომელიც არ უნდა გამოგრჩეს.

    -როცა საჭიროა მონაცემების შეყვანა ძირითადი ეკრანის დატოვების გარეშე.


    5. როდის არ გამოვიყენოთ?

    -როცა გინდა, რომ მომხმარებელმა შეძლოს ეკრანის სხვა ნაწილებზე გადასვლა მოდალის დახურვის გარეშე.

    -როცა გჭირდება რთული ნავიგაცია ან მრავალსაფეხურიანი ფორმა.

    -როცა გინდა, რომ მომხმარებელმა შეძლოს მოდალის უკან დატოვება და სხვა რამის გაკეთება.


    მოკლედ რომ ვთქვათ: <Modal> არის „პატარა ფანჯარა“, რომელიც „ფარავს“ ეკრანს და აიძულებს მომხმარებელს, რომ დაასრულოს კონკრეტული მოქმედება, სანამ ის გააგრძელებს აპლიკაციის გამოყენებას.


    აი, კიდევ ერთი მარტივი მაგალითი, რომ უკეთ გაიგო:

    წარმოიდგინე, რომ შენს აპლიკაციაში მომხმარებელს სურს თავისი პროფილის სურათის შეცვლა.

    როცა ის დააჭერს ღილაკს „შეცვლა“, შენ გამოგიჩენ მოდალს, სადაც იქნება: სურათის გადახედვა, „გაუქმება“ და „შენახვა“ ღილაკები.

    ამ დროს მომხმარებელი ვერ შეძლებს აპლიკაციის სხვა ნაწილებზე გადასვლას, სანამ არ დახურავს ამ მოდალს.

    როცა ის დააჭერს „შენახვას“, შენ შეინახავ სურათს და დახურავ მოდალს.

    როცა დააჭერს „გაუქმებას“, შენ უბრალოდ დახურავ მოდალს და არაფერს შეინახავ.

    ეს არის ზუსტად ის სიტუაცია, როცა <Modal> არის საჭირო.
